## How I learn
 
I work in a lab where breaking things is allowed, and I treat every exercise the same way:
 
1. **Run the command**, knowing what I expect it to do
2. **Check the result** with a second command instead of assuming it worked
3. **Write down the mistakes**: what happened, why, and the fix
The notes I'm proudest of are the errors table: a command that "worked" but silently did something else teaches more than one that worked the first time.
